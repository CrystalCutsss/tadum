# Tadum v8 — карточки документов не переставляются

Выпуск по правке экрана документов клиента (решение Кирилла 2026-11-10). Данные — мок с персонами, бэкенда нет.

## Что вошло

- После загрузки документа его карточка остаётся на том же месте и не уезжает вниз: порядок карточек фиксируется при открытии экрана (наверху — документы, где нужно действие) и пересчитывается только при новом открытии или новом раунде

## Что отложено

- Раздел «Отправлено ранее» (файлы прошлых раундов) — нужен новый метод API
- Главная клиента пока заглушка; экран документов открывается пунктом «Documents» в сайдбаре
- Видео и пример — образцы-заглушки до материалов upload-портала; видео только на арабском
- Тексты на арабском и английском ждут проверки носителем (`docs/i18n/needs-review.md`)

## Известные ограничения

- Мок хранит состояние в браузере: выбор сценария в меню начинает его с исходных данных
- Кнопки в панели под карточкой — 32 px (решение Кирилла 2026-11-10), меньше прежних 44 px
- Проверка во встроенном браузере WhatsApp не проводилась

## Как смотреть

- Ссылка: https://proto.kirillgloba.workers.dev/p/tadum/v8/ — нужны два пароля: общий пароль витрины и отдельный пароль Tadum (у Кирилла)
- Меню в правом нижнем углу → «Сценарии и роли» → «Клиент: новая заявка», «Клиент: нужен новый файл» или «Клиент: дозапрос документов», затем «Documents» в сайдбаре
- Язык и тема — кнопками в шапке кабинета

## Что проверить команде

- Новая заявка: загрузить файл в документ посередине списка — карточка остаётся на месте, бейдж меняется на «Uploaded»
- Нужен новый файл: загрузить новый файл в верхний документ — карточка остаётся первой

## Откат

Витрина собирается из `main` Proto: откат — revert публикации v8 в Proto (или Rollback в дашборде Cloudflare Workers). v1–v7 не затрагиваются.
