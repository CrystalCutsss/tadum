# ADR-004 — Один PR — одна публикация

**Статус:** принят Кириллом 2026-11-06, ждёт настройки (секрет и workflow) · **Дата:** 2026-11-06 · **Изменяет:** ADR-003 (порядок публикации)

**Контекст.** До сих пор выпуск версии vN занимал три-пять веток и PR: код Tadum, версия в Proto (`feat/tadum-vN`), release notes, плюс ручной тег. Кирилл: «Мне надо 2 вещи: быстро смотреть правки без публикации и ОДНА публикация с ОДНИМ PR».

**Решение.**

1. **Просмотр без публикации** — превью ветки `https://<ветка>-tadum.kirillgloba.workers.dev` (A-053): CI выкладывает его примерно через минуту после push в рабочую ветку. PR для этого не нужен.
2. **Одна ветка и один PR на выпуск.** В PR входят код и `docs/releases/vN.md`. Отдельных веток и PR для release notes, тега и Proto больше нет.
3. **Публикация — автоматически после merge.** Workflow `.github/workflows/release.yml` срабатывает при push в `main`, если появилась `docs/releases/vN.md`, которой ещё нет в Proto. Он:
   - запускает `pnpm run release:proto --ci`, который собирает vN;
   - коммитит замороженную версию прямо в `main` Proto (только `prototypes/tadum/**`, ADR-0028 Proto);
   - ставит тег `vN` и создаёт релиз GitHub с текстом release notes.

   Витрину выкладывает Workers Builds Proto.
4. Merge PR в Tadum — это и есть «да» на публикацию (D-069). PR без `docs/releases/vN.md` ничего не публикует.
5. Изменения самой оболочки Proto (`packages/**`) по-прежнему идут отдельным PR в Proto: это другой репозиторий и другие прототипы.

**Последствия.**
- Кириллу нужно один раз поставить секрет `PROTO_PUSH_TOKEN` в репозитории Tadum: fine-grained PAT на `CrystalCutsss/proto`, Contents — Read and write. Агент его не видит (D-068).
- В облачной сессии файлы `.github/**` и `.claude/settings.json` защищены хуком: workflow из `docs/setup/pending/release.yml` переносит Кирилл или сессия с `TADUM_ALLOW_PROTECTED=1`.
- Защиты веток на бесплатном плане нет (A-048), поэтому merge с красным CI опубликует версию. Мержить только зелёный PR.
- **Proto не ломается.** Публикация коммитит только `prototypes/tadum/**` и запись нового пакета в `pnpm-lock.yaml`. Если затронут любой другой файл, автоматическая публикация из CI не выполняется. При ручном запуске в сессии агент показывает эти файлы Кириллу и продолжает только после его «да» (`--allow-proto-files`; решение Кирилла 2026-11-06). Перед push в Proto проходят `registry:validate`, `lint` и `site:build` всей витрины; после push Proto гоняет свой CI на `main`. Опубликованные версии и другие прототипы не трогаются (ADR-0010 Proto).
- Правило «одна задача — одна ветка — один PR» — инвариант 13 в `CLAUDE.md`, действует для любой задачи и любой сессии.
- Откат прежний: revert коммита публикации в `main` Proto или Rollback в Cloudflare.
