# SC-04 · Дозапрос документов после проверки

| Поле | Значение |
|---|---|
| **ID** | `SC-04` |
| **Роли** | `client_contact`, `client_owner` |
| **Экраны** | `client.home`, `client.documents`, `client.document` |
| **Предусловие** | Комплект раунда 1 был отправлен и проверен; UW перевёл заявку в `Need more docs for UW` и создал новый комплект (`round = 2`) только с недостающими документами; старый комплект `superseded` |
| **Статусы** | `client_status = docs_required` (снова), `permission_state = collecting`; новый `DocumentSet.status = draft` |
| **Цель** | Клиент не воспринимает дозапрос как откат назад: видит, что проверка идёт и нужно добавить несколько документов, и делает это за один заход |
| **Метрика** | Доля дозапросов, закрытых клиентом в течение 48 часов; доля заявок с ≥ 2 раундами (чем меньше, тем лучше — сигнал для подсказок в SC-02) |
| **Версия прототипа** | v2 |
| **Персоны мока** | `client_more_docs` (раунд 2, два документа: один новый тип, один повторный с причиной) |
| **Связанные документы** | `01-cabinet-structure.md` §5 (D-008), `01-entities.md` §2.4, `01-statuses.md` §2, §4, §10 (`uwRequestMoreDocs`) |
| **Статус** | черновик — живой каркас (вопросы закрыты) |

---

## 1. Основной сценарий

```
Дано:  раунд 1 отправлен (SC-02), заявка была under_review (SC-05);
       UW вызвал uwRequestMoreDocs([vat_sales, ch_owner]) → новый комплект round 2 в draft,
       старый комплект superseded, client_status = docs_required
Когда: клиент открывает /c/home (по WhatsApp-ссылке или сам)
Тогда: шкала НЕ откатывается (D-008): «Документы» в состоянии needs_attention с меткой
       timeline.needs_more_docs, «Проверка» остаётся current;
       карточка next_step.more_docs_requested {count: 2} с CTA → /c/documents;
       событие screen_viewed {round: 2}

Когда: клиент открывает /c/documents
Тогда: сверху блок documents.more_docs_banner «Нам нужно ещё {count} документа»;
       список = только документы нового комплекта (2 шт.), все pending (или rejected, если
       повторный документ отклонён с причиной — тогда как в SC-03);
       ниже сворачиваемый раздел documents.previous_round «Отправлено ранее ({n})» — документы
       раунда 1 только для чтения, со статусами approved/received и кнопкой «Скачать»;
       прогресс «Загружено 0 из 2»; кнопка «Отправить на проверку» задизейблена

Когда: клиент загружает оба документа (путь SC-02) и нажимает «Отправить на проверку»
Тогда: новый комплект submitted → in_review; client_status → under_review;
       шкала: «Документы» done, «Проверка» current; метка needs_attention снята;
       событие document_set_submitted {round: 2, documents_count: 2}
```

Ключевое отличие от SC-02: в списке только то, что нужно сейчас; всё уже принятое — под сворачиваемым разделом; формулировки подчёркивают, что проверка продолжается, а не началась заново.

## 2. Альтернативные сценарии и ошибки

| # | Условие | Что видит (ключ) | Действие | Событие |
|---|---|---|---|---|
| A1 | В новом комплекте документ, который уже был в раунде 1, с причиной отклонения | Строка как в SC-03 (причина + «Загрузить заново»); в разделе «Отправлено ранее» этот документ помечен `superseded` | как SC-03 | `rejected_document_viewed` |
| A2 | Новый комплект содержит документ без ассетов | Карточка без примера/видео (D-026) | — | — |
| A3 | Раунд 3 и далее | То же поведение; в баннере — без номера раунда (не демотивируем); аналитика фиксирует `round` | — | `screen_viewed {round}` |
| A4 | Клиент открывает старый документ из «Отправлено ранее» | Карточка только для чтения: файлы, «Скачать», статус; без зоны загрузки | — | `document_file_downloaded` |
| A5 | Odoo создал новый комплект, но он пуст (ошибка данных) | Пустое состояние `documents.empty_waiting` + SupportBar; шкала без `needs_attention` | — | `data_inconsistency {kind: empty_round}` |
| A6 | Клиент не заходил несколько дней после дозапроса | Ничего особенного в UI; напоминания — через WhatsApp (вне портала) | — | — |
| A7 | Отправка нового комплекта при офлайне | Кнопка задизейблена с подсказкой | — | — |
| A8 | Гонка: UW создал раунд 3, пока клиент заполнял раунд 2 | При следующем запросе данных список обновляется, баннер `documents.list_updated`; введённое по старым документам сохраняется, если они есть в новом комплекте | — | `data_refreshed {reason: new_round}` |

## 4. Тексты интерфейса (AR / EN) — предложение

| Ключ | EN | AR | Примечание |
|---|---|---|---|
| `timeline.needs_more_docs` | A few more documents needed | نحتاج بضعة مستندات إضافية | метка на шаге «Документы» |
| `next_step.more_docs_requested` | Our team reviewed your documents and needs {count} more to continue | راجع فريقنا مستنداتك ويحتاج {count} مستندات إضافية للمتابعة | формы множ. числа |
| `documents.more_docs_banner.title` | Almost there — {count} more documents | اقتربنا — {count} مستندات إضافية | «almost there» проверить на TOV (не обещание) |
| `documents.more_docs_banner.body` | Everything you sent earlier is safe with us. Add the documents below and send them for review | كل ما أرسلته سابقًا محفوظ لدينا. أضف المستندات أدناه وأرسلها للمراجعة | |
| `documents.previous_round` | Sent earlier ({count}) | أُرسلت سابقًا ({count}) | сворачиваемый раздел |
| `documents.previous_round.hint` | These documents don't need any action | هذه المستندات لا تحتاج إلى أي إجراء | |
| `document.status.superseded` | Replaced | تم استبداله | бейдж для документа старого раунда, который запрошен заново |
| `documents.list_updated` | Your document list was updated | تم تحديث قائمة مستنداتك | баннер при A8 |
| `documents.submit` | Send for review | إرسال للمراجعة | = SC-02 |

Избегаем слов «снова», «заново», «повторно» в заголовках — они читаются как откат. «Загрузить заново» остаётся только для конкретного отклонённого файла (SC-03).

## 6. Критерии приёмки

- [ ] Шкала прогресса не откатывается: «Проверка» остаётся `current`, «Документы» получает `needs_attention` (таблица истинности `01-statuses.md` §8, строка `round ≥ 2`).
- [ ] В основном списке только документы нового комплекта; документы прошлого раунда — в свёрнутом разделе, только для чтения.
- [ ] Повторно запрошенный документ показывает причину по правилам SC-03; старый файл помечен `superseded`.
- [ ] Отправка нового комплекта переводит заявку в `under_review`, метка `needs_attention` снимается.
- [ ] Тексты не содержат слов, читающихся как откат («снова», «заново») в заголовках и баннере; тон спокойный.
- [ ] Персона `client_more_docs` воспроизводит сценарий, включая раскрытие прошлого раунда; демо-панель умеет вызвать `uwRequestMoreDocs` из состояния `client_submitted`.
- [ ] Тексты в `ar` и `en`; множественное число для `{count}`.
- [ ] axe без нарушений; сворачиваемый раздел — `aria-expanded`, метка на шкале озвучивается.
- [ ] Storybook: `StatusTimeline` more-docs; `client.documents` more-docs / partial / complete / previous-expanded × AR/EN × light/dark.
- [ ] Playwright: из `client_submitted` → `uwRequestMoreDocs` → загрузка → отправка → `under_review`; A1, A4.

## 7. Заметки для реализации

- `deriveTimeline` получает `round` из текущего комплекта; для `round ≥ 2` и `docs_required` возвращает `needs_attention` для `documents` и `current` для `review`.
- Старые комплекты приходят в данных вместе с текущим (`application.document_sets[]`) или отдельным вызовом порта `listDocumentSets(applicationId)` — решить в контракте портов; для мока — массив.
- Баннер `documents.more_docs_banner` показывается, пока новый комплект в `draft`; после отправки заменяется на `documents.submitted_banner`.

## 8. Открытые вопросы

Решено (Кирилл, 2026-11-04): SC4-1 — в новый комплект входят только недостающие документы (закрывает также S-3 в `01-statuses.md`, D-031). SC4-2 — клиенту показываем только причины по документам (согласованные теги); общий комментарий UW к дозапросу не показываем (D-032).
