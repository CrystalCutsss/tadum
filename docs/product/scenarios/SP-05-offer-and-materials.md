# SP-05 · Условия Tadum и материалы для клиентов

| Поле | Значение |
|---|---|
| **ID** | `SP-05` |
| **Роли** | `supplier`, `dual` |
| **Экраны** | `supplier.offer` (`/s/offer`), пункт «Условия» в меню «Ещё» |
| **Предусловие** | Поставщик в кабинете; порт `OfferPort.get()` отдаёт `OfferContent` (один текст условий для всех и список материалов, SFL-801) |
| **Статусы** | Любой `supplier_status` — раздел доступен всегда |
| **Цель** | Поставщик понимает, что он получает от работы с Tadum и как проходит сделка, и за одно нажатие скачивает материал, который можно переслать клиенту |
| **Метрика** | Доля поставщиков, скачавших хотя бы один материал за месяц (`material_downloaded`); связь скачиваний с заявками по ссылке (через 4–6 недель) |
| **Версия прототипа** | v5 (P2) |
| **Персоны мока** | `supplier_active`, `supplier_new`; `OfferContent` в моке: условия AR/EN (3–5 абзацев-заглушек из согласованного TOV), 4 материала: 2 PDF (`both`), 1 видео AR, 1 PDF EN |
| **Связанные документы** | `01-entities.md` §2.12; `01-roles.md` §5 (`view_offer_terms`, `download_materials`); `01-cabinet-structure.md` §1; `SC-10` (IAB, офлайн); D-017, D-026 (ассеты) |
| **Статус** | черновик — живой каркас |

## 1. Основной сценарий

```
Дано:  поставщик открыл /s/offer
Тогда: две вкладки (Tabs): «Условия» (по умолчанию) и «Материалы»; событие screen_viewed {screen_id: supplier.offer, tab: terms}

Вкладка «Условия»:
       RichText на языке интерфейса (terms.ar / terms.en): что получает поставщик, как проходит сделка
       (клиент выбирает товар → квотация на компанию клиента → Tadum покупает у поставщика и платит ему →
       клиент платит Tadum частями); блок «Есть вопросы?» с SupportBar; текст один для всех (индивидуальные
       условия — фаза 2)

Когда: переключает на «Материалы»
Тогда: список карточек: иконка типа (PDF / видео), название на языке интерфейса, язык материала (AR / EN / AR+EN),
       размер, кнопка «Скачать» (PDF) или «Открыть» (видео); вкладка — в URL (?tab=materials);
       событие offer_tab_changed {tab: materials}

Когда: нажимает «Скачать» у PDF
Тогда: прямая ссылка download_url с атрибутом download, открывается в новом окне (не blob:, см. DoD);
       событие material_downloaded {id, kind: pdf, lang}

Когда: нажимает «Открыть» у видео
Тогда: открывается встроенный плеер (Dialog) или, в IAB, прямая ссылка в новом окне;
       событие material_opened {id, kind: video, lang}

Когда: нажимает «Поделиться» у материала
Тогда: Web Share с {title, url: download_url}, иначе — копирование ссылки на материал (как в SP-02);
       событие material_shared {id, method}
```

Материалы — общие для всех поставщиков (без логотипа и ссылки поставщика — фаза 2). Сами файлы живут на стороне Tadum (CDN/лендинг), портал хранит только `download_url`; в моке — несколько заглушечных PDF из `public/mock/`.

## 2. Альтернативные сценарии и ошибки

| # | Условие | Что видит (ключ) | Действие | Событие |
|---|---|---|---|---|
| A1 | Материалов нет (`materials = []`) | Вкладка «Материалы» остаётся, внутри — `offer.materials_empty` без CTA | — | — |
| A2 | Материал только на одном языке, интерфейс — на другом | Карточка показывается с бейджем языка (`offer.lang.ar` / `offer.lang.en`); не скрываем (поставщик может отправить клиенту, говорящему на другом языке) | — | — |
| A3 | Открыто в IAB WhatsApp | PDF — прямая ссылка в новом окне (WhatsApp сам предложит открыть/сохранить); видео — внешняя ссылка вместо встроенного плеера | — | `material_downloaded {method: external}` |
| A4 | Офлайн | «Условия» — из кэша; у материалов кнопки неактивны с подписью `common.offline_action_hint` | — | — |
| A5 | `download_url` не отвечает (404/500) | Браузерная ошибка в новом окне; в портале — тост `offer.download_failed` с «Повторить» по событию ошибки, если удалось отследить | повторить | `material_download_failed {id}` |
| A6 | Условия обновились (новая версия `terms`) | Без уведомления в MVP; версия текста — поле `updated_at`, показываем «Обновлено {date}» под заголовком | — | — |
| A7 | Текст условий содержит ссылки на внешние документы (договор поставщика) | Ссылки открываются в новом окне; подпись договора в портале — вне объёма | — | `offer_external_link_clicked {href_host}` |
| A8 | Длинный текст условий на арабском | Типографика RichText: заголовки h2/h3, списки, абзацы; ширина строки ограничена; якоря к разделам в URL | — | — |
| A9 | `dual`: клиент заходит в «Условия» поставщика | Доступно только в роли supplier; в клиентском кабинете этого раздела нет | — | — |
| A10 | Видео на арабском открыто в EN-интерфейсе | Пометка `document.video_arabic_only` (ключ из SC-02) | — | — |

## 6. Критерии приёмки

- [ ] Раздел доступен в любом `supplier_status`; в клиентском кабинете отсутствует.
- [ ] Условия — RichText на языке интерфейса из `OfferContent.terms`; смена языка переключает текст без перезагрузки; «Обновлено {date}» из данных.
- [ ] Материалы: карточка показывает тип, язык, размер; PDF скачивается прямой ссылкой (не `blob:`), видео открывается во встроенном плеере, в IAB — внешней ссылкой; материалы на «чужом» языке не скрываются.
- [ ] «Поделиться» — Web Share или копирование ссылки, обратная связь на кнопке (как SP-02).
- [ ] Пустое состояние и офлайн-режим — по §3; ошибки скачивания не ломают экран.
- [ ] Тексты в `ar` и `en`; axe без нарушений; вкладки — Radix `Tabs` с клавиатурной навигацией; у видео есть текстовое название и `aria-label`.
- [ ] Storybook: `OfferTerms` normal / loading / long-arabic; `MaterialsList` normal / empty / offline; `MaterialCard` pdf/video × ar/en/both × AR/EN × light/dark.
- [ ] Playwright: `supplier_active` → `/s/offer` → вкладка «Материалы» (URL `?tab=materials`) → скачивание PDF (проверка `download` события) → открытие видео → эмуляция IAB → внешняя ссылка.

## 7. Заметки для реализации

- `OfferPort.get()` — отдельный порт с кэшированием через TanStack Query (`staleTime` большой: контент меняется редко). Источник контента и в моке, и после подключения бэкенда — статический JSON `content/offer.{ar,en}.json` в репозитории, валидируется Zod-схемой `OfferContent` на сборке; `HttpAdapter` для этого порта не нужен, пока нет CMS (D-041).
- RichText — ограниченное подмножество (заголовки, абзацы, списки, ссылки, жирный); рендер через безопасный компонент без `dangerouslySetInnerHTML` с произвольным HTML (санитизация или собственный AST).
- Видео-плеер — нативный `<video>` без сторонних библиотек; постер и `preload="none"`, чтобы не тянуть трафик на мобильном.
- Компонент карточки материала переиспользует `document.video_arabic_only` и детекцию IAB из SC-02/SC-10.
- P2 / v5: в v3–v4 пункт «Условия» в меню «Ещё» скрыт флагом `features.offer` (из `shared/config`), маршрут `/s/offer` редиректит на `/s/home`; заглушки «скоро» нет (D-042). Включение флага = появление пункта и маршрута без других правок.

## 8. Открытые вопросы

Решено (Кирилл, 2026-11-04):

- **SP5-1** — после подключения бэкенда текст условий и список материалов берутся из статического JSON в репозитории Tadum (`content/offer.{ar,en}.json`), обновляются PR-ом; перенос в CMS — когда она появится (D-041).
- **SP5-2** — до готовности контента (v5) пункт «Условия» в меню скрыт, маршрут `/s/offer` отвечает редиректом на `/s/home`; заглушку «скоро» не показываем (D-042).

Открытых вопросов по сценарию нет.
