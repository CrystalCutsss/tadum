**Overview**

Личный кабинет поставщика на сайте Tadum. После входа поставщик видит свои документы и статусы, реферальную ссылку, приведённых клиентов (статус и оборот с ним) и предложение Tadum: условия и материалы для клиентов.

**Problem**

После того как поставщик привёл клиента, он не видит, что происходит дальше. Статусы лидов есть только у команды Tadum в Odoo.

**Что есть сейчас**

- У каждого поставщика есть реферальная ссылка `tadum.sa/s/{slug}`, лиды помечаются автоматически (SFL-488).

- Upload-портал поставщика `upload.tadum.sa/supplier`: три документа (VAT certificate, IBAN letter, National Address).

**Что должно быть в ЛК поставщика в общем**

Поставщик входит по номеру телефона и коду ОТП - авторизация технически такая же, как в ЛК клиента. В кабинете он видит:

1. свой статус и следующий шаг: что нужно сделать ему или что сейчас делаем мы;

2. свои документы со статусами «pending / received / rejected (+причина)», может догрузить или заменить файл;

3. после одобрения всех документов - видит реферальную ссылку: скопировать, отправить в WhatsApp, скачать QR-код;

4. предложение Tadum: условия работы и материалы, которыми можно делиться с клиентами.

**Functional requirements**

Вход и роли

- Вход, привязка телефона к поставщику, выбор роли, переключатель AR/EN и контакты поддержки

- сценарии авторизации и входа как для ЛК клиента. Основное:

| Сценарий | Что видит поставщик |
| --- | --- |
| Оставил заявку и ввел код ОТП, сбор документов | сообщение в WA со ссылкой на ЛК, Экран Application в ЛК раздел Documents |
| Оставил заявку, но код ОТП не ввел / оставил повторную заявку, не введя код для первой | необходимо подтвердить код, чтобы авторизоваться, поэтому поставщик видит экран с ОТП пока он его не подтвердит. Если подана новая заявки при неподтвержденной первой - первую в LOST |
| Успешный вход в ЛК по коду | Заявку на текущей стадии (статусы описаны в таблице ниже) |
| Попытка входа в ЛК без наличия подтвержденной компании | Открывается форма для подачи без переброса обратно на лэндинг |
| Подача заявки на лэндинге при наличии уже существующей активной заявки | Открывается форма OTP, затем экран существующей заявки на текущей стадии |
| Поставщик не ввел код, но до него дозвонился телесейлз | Поставщик остаётся неподтверждённым, пока не введёт код. |
| Неверный код, код истёк, много попыток | Текст ошибки и таймер; после 5 неверных вводов код сгорает. |
| Номер привязан к нескольким поставщикам | Выбор компании после входа |
| Телефон поставщика сменили в Odoo | Старый номер теряет доступ, новый подтверждается кодом |
| Поставщик в Lost | Кабинет только для чтения: «Работа приостановлена, свяжитесь с нами». Возврат кнопкой Return to Processing в Odoo |
| Поставщик в Declined | Нейтральный экран без причины, доступ закрыт |
| Партнёр с тегом Partner, а не поставщик | Тот же кабинет без блока про сделки |
| Сессия истекла, выход | «Сессия завершена, войдите снова» |

Главная (Home): статус и следующий шаг

- Таймлайн (маппинг из стадий Odoo): Документы → Проверка → Активен.

- Виден следующий шаг и на чьей он стороне. Примеры: «Загрузите недостающие документы», «Проверяем документы, ожидайте», «Вы активны: делитесь ссылкой».

Документы

- Правила те же, что у клиента: статус по каждому документу; отклонённый поднимается наверх с текстом причины; после отправки править нельзя, пока документы не проверят; подсказки, примеры и видео переносятся из upload-портала.

- Набор документов задаёт Odoo (сейчас: VAT certificate, IBAN letter, National Address, при необходимости CR).

Реферальная ссылка

- Ссылка с кнопками «Скопировать» и «Поделиться в WhatsApp» (готовый текст на AR/EN).

- QR-код ссылки, который можно скачать для печати.

- Редактировать свою реферальную страницу поставщик не может.

Приведённые клиенты

- В списке все лиды, привязанные к поставщику: по его ссылке и привязанные вручную командой Tadum. Если клиента привели два поставщика, он виден обоим.

- Для каждого: название компании, дата заявки, статус, оборот клиента с этим поставщиком (SAR), дата последнего изменения. Фильтр по статусу, сортировка по дате.

- Оборот в списке: сумма сделок этого клиента, где данный поставщик указан поставщиком. Другие поставщики клиента не видны.

- Телефон клиента, одобренный лимит и причина закрытия поставщику не показываются.

Статусы заявки клиента, которые мы отображаем поставщику:

| Отображаем поставщику в ЛК | Стадии клиента в Odoo |
| --- | --- |
| Application in progress | New lead, Processing lead, Document collection, Need more docs for UW, Ready for UW, Company risk assessment, Risk committee |
| Application approved | Approved, Offer confirmation, Signing SPA & PN, Client Approved |
| Application rejected | Rejected, LOST |
| Deal in progress | (OPS) ready to get supplier quotation → (Sales) Customer invoice created |
| Deal completed | Deal closed |
| Deal rejected | отказ UW или Lost по любой причине |

- Материалы про Tadum доступны для поставщика на любой стадии подачи заявки: (PDF и видео для клиентов, скачать одним нажатием, AR/EN).

**Scope**

приоритеты по MVP

| Приоритет | Что входит |
| --- | --- |
| MVP (обязательно для релиза) | - вход (общий), статус поставщика и следующий шаг, документы (статусы, перезагрузка, блокировка после отправки, предвалидация), реферальная ссылка с QR, список приведённых клиентов со статусом и оборотом AR/EN; контакты поддержки на каждом экране |
| Фаза 2 | вознаграждение поставщика (фикс или доля, схема не решена) и его учёт, индивидуальные условия для крупных поставщиков, уведомления в WhatsApp при смене статуса лида, материалы с логотипом и ссылкой поставщика, сделки с поставщиком (объём закупок Tadum у него), геймификация, предложение «купить с отсрочкой» для поставщика-клиента. |

**Out of scope**

- Подпись договора поставщика в портале.

- Редактирование своей реферальной страницы (SFL-850).

- Геймификация (отдельный тикет).

**Why / Value**

Поставщики, которые видят движение своих клиентов и свой оборот с ними, продолжают приводить новых и подталкивают их закончить заявку. Это же снимает вопросы о статусах с команды продаж.

**For whom**

Поставщики, приводящие клиентов в Tadum (малые и крупные).

**Success metrics**

- Доля приводящих поставщиков, которые заходят в кабинет хотя бы раз в месяц.

- Supports: O1 KR2, assessed leads from small suppliers 12 → 30 / 70 / 150.

- Сравнение доли заявок, дошедших до assessed, у поставщиков с кабинетом и без. Через 4–6 недель после запуска согласуем, что считаем успехом.

- События для аналитики с первого релиза: вход, копирование ссылки, отправка в WhatsApp, скачивание QR, скачивание материала, открытие списка клиентов. Аналитика на событиях и A/B-тесты ведутся в SFL-895
