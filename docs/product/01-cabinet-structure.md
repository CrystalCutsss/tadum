# 01 · Структура кабинета

**Проект:** Tadum · **Раздел:** Требования к продукту · **Версия:** 1.6 · **Дата:** 2026-11-06 · **Статус:** согласовано как базовый каркас (C-1…C-3 закрыты); раздел 2 «Оболочка» — по решению Кирилла 2026-11-06 (сайдбар `sidebar-08`)
**Источники:** требования к кабинету клиента и поставщика, решения D-007, D-008, D-014, D-016, D-020, D-023, D-024, D-025, D-038. **Связанные документы:** `01-roles.md`, `01-entities.md`, `01-statuses.md`.

> Одна оболочка на две роли. Документ описывает маршруты, общие элементы оболочки, переключение ролей/языка/темы, шкалу прогресса и карточку «следующий шаг», терминальные экраны и диплинки. Идентификаторы маршрутов и экранов (`screen_id`) — стабильные ключи для сценариев, аналитики, Storybook и Playwright.

## 1. Карта маршрутов → код

Маршруты — файловые (TanStack Router). Префикс `/c` — кабинет клиента, `/s` — кабинет поставщика. Все маршруты под префиксами защищены гардом «есть сессия и есть роль этой семьи».

| Маршрут | `screen_id` | Роль | Гард | Назначение | Приоритет | Версия |
|---|---|---|---|---|---|---|
| `/` | — | все | — | Редирект: нет сессии → `/login`; есть `active_role` → `/c/home` или `/s/home`; `dual` при первом входе → `/c/home` (D-020) | P0 | v1 |
| `/login` | `auth.phone` | все | нет сессии | Ввод телефона (канал кода выбирает бэкенд, D-027) | P0 | v1 |
| `/login/code` | `auth.otp` | все | телефон введён | Ввод кода, повтор через таймер, ошибки | P0 | v1 |
| `/not-found` | `auth.not_found` | `unknown` | — | «Заявка не найдена»: «Подать заявку», «Связаться с поддержкой» | P1 | v1 (D-067; SC-01 A8) |
| `/c/home` | `client.home` | client | — | Статус заявки, шкала прогресса, карточка следующего шага, сводка документов; после одобрения здесь же блоки `#limit` (лимит, чек-лист SPA/PN) и `#how-to-buy` (D-023) | P0 | v1 (блоки лимита — v4) |
| `/c/documents` | `client.documents` | client | — | Комплект документов: список, статусы, причины, загрузка, отправка | P0 | v2 (в v1 — заглушка «появится в v2», D-067) |
| `/c/documents/:portalKey` | `client.document` | client | документ есть в комплекте | Карточка документа: подсказка, пример PDF, видео, файлы, загрузка/замена | P0 | v2 |
| `/c/closed` | `client.closed` | client | `client_status == closed` | Нейтральный текст, путь к новой заявке, поддержка | P1 | v4 |
| `/c/reapply` | `client.reapply` | client | `client_status == closed` | Повторная заявка (D-038): в v1 заглушка с текстом и кнопкой «Создать заявку»; создаёт новую заявку, старая остаётся закрытой | P1 | v4 |
| `/c/help` | `client.help` | client | — | Контакты поддержки, FAQ-ссылки (текст), язык, тема (D-025), выход | P0 | v1 |
| `/s/home` | `supplier.home` | supplier | — | Статус поставщика, следующий шаг, счётчики, короткая реферальная карточка | P0 | v3 |
| `/s/referral` | `supplier.referral` | supplier | — | Ссылка, «Скопировать», «Поделиться в WhatsApp», QR для печати | P0 | v3 |
| `/s/clients` | `supplier.clients` | supplier | — | Приведённые клиенты: список, фильтр по статусу, сортировка по дате | P1 | v3 |
| `/s/documents` | `supplier.documents` | supplier | — | Документы поставщика (те же правила, что у клиента) | P1 | v3 |
| `/s/documents/:portalKey` | `supplier.document` | supplier | документ есть в комплекте | Карточка документа поставщика | P1 | v3 |
| `/s/offer` | `supplier.offer` | supplier | — | Условия Tadum (один текст) и материалы для клиентов (PDF/видео, AR/EN) | P2 | v5 |
| `/s/help` | `supplier.help` | supplier | — | Поддержка, язык, тема (D-025), выход | P0 | v3 (в v1 — заглушка вместе с `/s/home`, D-067) |
| `/session-expired` | `auth.expired` | все | — | Сессия истекла, кнопка «Войти» | P0 | v1 |
| `/offline` | — | все | — | Не маршрут, а состояние оболочки (баннер); см. раздел 7 | P0 | v5 |
| `*` | `system.404` | все | — | Нейтральный 404 с кнопкой «На главную» | P0 | v1 |

Правила маршрутизации:

- Прямой переход на маршрут другой семьи (например, клиент открыл `/s/home`) → редирект на свой `home`, без ошибки.
- `dual` может открыть любой маршрут обеих семей; `active_role` переключается на семью маршрута автоматически (диплинк из WhatsApp должен работать без лишних экранов).
- Гард прав (`client_status == closed` для `/c/closed` и `/c/reapply`) при неудаче ведёт на `home` своей роли, а не на 404. Право `view_limit` управляет видимостью блоков `#limit` / `#how-to-buy` на `home`, отдельного маршрута у лимита нет (D-023).
- Базовый путь приложения берётся из `import.meta.env.BASE_URL`, чтобы сборка работала и в корне, и под `/p/tadum/vN/` на витрине.

## 2. Оболочка (shell)

> Решение Кирилла 2026-11-06: каркас кабинета — сайдбар на основе shadcn `sidebar-08` (вариант `inset`). Реализация — PR CrystalCutsss/tadum#8, допущения — A-055 в `docs/decisions/assumptions.md`.

Оболочка одна для обеих ролей; меняются только пункты меню и данные.

```
┌────────────┬───────────────────────────────────────────────┐
│ tadum.     │ [≡] Заголовок страницы (крошки)        AR/EN  │ ← шапка контента
│            ├───────────────────────────────────────────────┤
│ Home       │                                               │
│ Documents  │  Контент: сетка 3 колонки (≥ 1024 px),        │
│            │  ниже — 1 колонка; экраны пока 2 из 3         │
│            │                                               │
│ ┌────────┐ │                                               │
│ │Помощь  │ │                                               │
│ │WA·Email│ │                                               │
│ └────────┘ │                                               │
│ Компания ⌃ │                                               │
│ Роль       │                                               │
└────────────┴───────────────────────────────────────────────┘
  сайдбар       контент — на всю ширину, в контейнере с обводкой

```

| Элемент | Поведение | Компонент (widgets) |
|---|---|---|
| Сайдбар | Серый фон; сверху вниз: словесный знак «tadum.» (Geist bold, строчные, точка синяя, в тёмной теме светло-серая) → основное меню → внизу (прилипает): блок помощи и аккаунт. Скрывается кнопкой в шапке, контент растягивается; состояние запоминается. RTL — справа, LTR — слева | `AppSidebar` |
| Сайдбар на телефоне (< 768 px) | Свёрнут в кнопку в шапке; открывается шторкой с полным меню; переход на другой экран закрывает шторку | `AppSidebar` |
| Основное меню | Home · Documents, без вложенных страниц; иконки 20 px, текст 14 px medium (как название компании); активный пункт выделен только фоном; цели ≥ 44 px | `AppSidebar` |
| Блок помощи | Card: заголовок «Have a question?» и подзаголовок «Message us» (мельче, regular, серый); кнопка WhatsApp (логотип, фирменный цвет; `wa.me/966579768881`) и вторичная «Email» (`info@tadum.sa`); событие `support_contact_clicked {channel}` | `SupportCard` |
| Аккаунт | Без аватара: название компании (клиент) или поставщика, подстрочник — текущая роль. Меню — по примеру shadcn Dropdown Menu «Complex», без шорткатов: группа «Account» со сменой роли Client / Supplier сверху вниз с иконками (только `dual`; подсказка один раз), разделитель, «Settings» → `/c/help` или `/s/help` и «Sign out» (красный, с подтверждением) | `NavAccount` |
| Шапка контента | Кнопка скрытия/раскрытия сайдбара · заголовок страницы (хлебные крошки, пока один уровень) · переключатель языка (ghost) — прижат к концу строки в RTL и LTR. Переключателя темы нет (D-025) | `AppHeader`, `LanguageSwitch` |
| Баннер офлайн | Появляется при потере сети, не блокирует чтение | `OfflineBanner` |
| Демо-панель (только витрина) | Персона, язык, тема, сеть, действия «от имени Odoo»; скрыта в проде флагом | `DemoPanel` |

Пункты основного меню по ролям:

| Роль | Пункты (порядок) |
|---|---|
| client | Home `/c/home` · Documents `/c/documents` (лимит — блок на главной, отдельного пункта нет, D-023) |
| supplier | Home `/s/home` · Documents `/s/documents` (до v3 — заглушка) |

«Помощь и настройки» открываются из меню аккаунта («Settings»), отдельного пункта в основном меню нет.

Открытый вопрос: пункты поставщика «Ссылка» `/s/referral`, «Клиенты» `/s/clients`, «Условия» `/s/offer` — добавлять ли их в основное меню, когда разделы появятся (v3/v5). По умолчанию — решать вместе с проработкой разделов.

Блок лимита на главной до одобрения не показывается вовсе (не задизейблен): клиент не должен видеть, чего ему «не хватает».

## 3. Язык, направление, тема

| Параметр | Правило |
|---|---|
| Язык по умолчанию | `ar`. Порядок приоритета: `?lang=` в URL → сохранённый выбор → `ar` |
| Переключатель | На каждом экране в шапке; сохраняется в браузере; событие `language_changed {to}` |
| Направление | `ar` → `<html dir="rtl" lang="ar">` + `DirectionProvider rtl`; `en` → `ltr`. Меняется без перезагрузки |
| Шрифты | `:lang(ar)` → IBM Plex Sans Arabic; `:lang(en)` → Geist (D-004) |
| Тема | По умолчанию **светлая**, независимо от темы браузера/устройства (D-079); ручной выбор `system / light / dark` — только в настройках (`/c/help`, `/s/help`), не в шапке; выбор хранится рядом с языком; класс `.dark` на `<html>` (D-016, D-025, D-079). `ThemeSwitch` живёт на экране настроек |
| Цифры | Западные 0–9 в обоих языках; телефон, IBAN, CR, суммы — в `<bdi dir="ltr">` |

## 4. Переключение ролей (`dual`)

| Правило | Описание |
|---|---|
| Где | В меню аккаунта внизу сайдбара — группа «Account» с пунктами Client / Supplier; видна, только когда `roles` содержит обе семьи |
| Что меняется | `active_role`, префикс маршрута, данные. Язык, тема, сессия, позиция в сопоставимом разделе сохраняются |
| Куда ведёт | На `home` выбранной роли (не пытаемся сопоставлять разделы между ролями) |
| Память | Последняя выбранная роль хранится в сессии и применяется при следующем входе |
| Первый вход | Без отдельного экрана (D-020): открывается клиентский кабинет `/c/home`. Один раз показываем ненавязчивую подсказку «У вас есть и кабинет поставщика — переключайтесь здесь»: на десктопе — у кнопки аккаунта, на телефоне — в шторке меню, когда её открыли |
| Событие | `role_switched {from, to}` |
| Индикатор | В аккаунте внизу сайдбара всегда видны название компании (клиент) или поставщика и, подстрочником, текущая роль |

## 5. Шкала прогресса (`StatusTimeline`)

Шкала — главный элемент `home`. Шаги фиксированы, их состояние вычисляется из статуса (см. `01-statuses.md`, раздел 2 и 3). Шкала **никогда не откатывается назад** (D-008).

```yaml
# → код: src/widgets/status-timeline/model.ts
TimelineStepState: 'done' | 'current' | 'upcoming' | 'needs_attention' | 'closed'

ClientTimeline:
  steps: [documents, review, decision, signing, limit_active]
  labels:            # ключи i18n
    documents:    timeline.client.documents
    review:       timeline.client.review
    decision:     timeline.client.decision
    signing:      timeline.client.signing
    limit_active: timeline.client.limit_active

SupplierTimeline:
  steps: [documents, review, active]
```

Вычисление состояния шагов клиента по `client_status`:

| `client_status` | documents | review | decision | signing | limit_active | Примечание |
|---|---|---|---|---|---|---|
| `docs_required` (первый комплект) | current | upcoming | upcoming | upcoming | upcoming | |
| `docs_required` (дозапрос, `round > 1`) | done | current | upcoming | upcoming | upcoming | Шаг «Проверка» остаётся текущим, «Документы» — пройдены. О дозапросе говорит баннер на экране документов (D-008, D-078) |
| `under_review` | done | current | upcoming | upcoming | upcoming | |
| `approved` (до подписания) | done | done | done | current | upcoming | |
| `approved` (всё подписано, лимит `active`) | done | done | done | done | current | |
| `first_purchase` | done | done | done | done | done | Шкала полностью пройдена; `home` показывает лимит и инструкцию |
| `closed` | — | — | closed | — | — | Шкала заменяется нейтральной карточкой «Заявка закрыта» |

Визуальные правила: в RTL шкала зеркальна (первый шаг справа); стрелки/шевроны зеркалятся, галочки — нет; `needs_attention` — цвет статуса `rejected`, не «ошибка системы»; у каждого шага доступное текстовое состояние (`aria-current`, `aria-label` с состоянием).

## 6. Карточка «следующий шаг» (`NextStepCard`)

Под шкалой всегда одна карточка: **на чьей стороне шаг** и что делать. Текст — только из ключей, тон — «персональный менеджер», без сроков-обещаний (кроме случаев, где срок приходит из данных).

```yaml
# → код: src/entities/application/model/next-step.ts
NextStep:
  owner: 'user' | 'tadum' | 'none'   # user — шаг на стороне клиента или поставщика (в зависимости от роли); tadum — на нашей стороне
  text_key: string          # i18n
  cta?: { label_key: string, route?: string, external_url?: string }
  meta?: { hours?: number, count?: number }   # подстановки в текст
```

Правила вывода (детерминированно из статуса, не из Odoo-текста):

| Ситуация | owner | text_key | CTA |
|---|---|---|---|
| `docs_required`, есть `rejected` документы | user | `next_step.reupload_rejected` (count) | → `/c/documents` |
| `docs_required`, нет отправленного комплекта | user | `next_step.upload_documents` (count оставшихся) | → `/c/documents` |
| `docs_required`, `round > 1`, новых загрузок нет | user | `next_step.more_docs_requested` | → `/c/documents` |
| `under_review` | tadum | `next_step.under_review` | — (SupportBar виден) |
| `approved`, чек-лист не завершён | user | `next_step.sign_documents` | → `/c/home#limit` (внутри — внешние ссылки Sadq/Nafith) |
| `approved`, чек-лист завершён, лимит `active` | user | `next_step.how_to_buy` | → `/c/home#how-to-buy` |
| `first_purchase` | none | `next_step.first_purchase_done` | — |
| `closed` | none | `next_step.closed` | → лендинг «Подать заявку» |
| supplier `docs_required` | user | `next_step.supplier.upload_documents` | → `/s/documents` |
| supplier `under_review` | tadum | `next_step.supplier.under_review` | — |
| supplier `active` | user | `next_step.supplier.share_link` | → `/s/referral` |

Текст «проверяем документы, это займёт N часов» показываем **только** если `meta.hours` пришёл из данных; иначе — формулировка без срока.

## 7. Состояния оболочки и системные экраны

| Состояние | Поведение |
|---|---|
| Загрузка данных маршрута | Скелетон в контенте, оболочка уже видна |
| Ошибка загрузки | Карточка «Не удалось загрузить» с «Повторить» и SupportBar; оболочка остаётся |
| Офлайн | Баннер сверху контента; действия загрузки/отправки задизейблены с подсказкой; чтение доступно |
| Сессия истекла (`401` от порта) | Редирект на `/session-expired`, после входа — возврат на исходный маршрут |
| Нет прав на маршрут | Редирект на `home` своей роли |
| 404 | Нейтральный экран с «На главную» |
| Обновление PWA | Тихое автообновление; тост «Доступна новая версия» — только при `major`-релизе (D-024) |

## 8. Диплинки и параметры URL

| Параметр / ссылка | Поведение |
|---|---|
| `?lang=ar|en` | Устанавливает язык и сохраняет его; убирается из URL после применения |
| Ссылка из WhatsApp на `/c/documents` | Без сессии → `/login` с запоминанием `returnTo`; после входа — на `/c/documents` |
| `/s/{slug}` на лендинге | Реферальная страница поставщика — **вне кабинета**, не маршрут портала |
| `?persona=<id>` (только витрина) | Загружает фикстуру-персону в мок; хранится в URL, чтобы ссылку можно было отправить коллеге |
| `?demo=1` (только витрина) | Показывает демо-панель |

## 10. Открытые вопросы

Решено (Кирилл, 2026-11-04): C-1 — лимит и чек-лист пока живут на `home` после одобрения, отдельного маршрута `/c/limit` нет (D-023). C-2 — обновление PWA тихое, тост только при `major` (D-024). C-3 — тема включается автоматически по теме браузера/устройства, ручной переключатель только в настройках; на витрине обе темы проверяются через демо-панель (D-025).

Открытых вопросов по структуре кабинета нет.
