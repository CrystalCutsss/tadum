# Снимок продуктовых документов

- `docs/product/**` — дословная копия Google Drive (шапка `<!-- source: Drive … -->`). Руками не править никогда.
- Обновление — только скилл `/sync-product-docs` в ветке `docs/sync-product-docs-*`, отдельный PR `docs: sync product docs YYYY-MM-DD`. Запускает Кирилл или агент после правки Drive (ниже); merge — Кирилл.
- Код при расхождении с документом не «чинит» документ: решение фиксируется в Drive, допущение до решения — в `docs/decisions/assumptions.md`.

## Правка документа в Drive агентом (решение Кирилла 2026-11-09)

Документы остаются в markdown (`.md`); перевод в Google Docs отклонён — теряет строки таблиц и экранирует символы.

1. Основание — только решение Кирилла в чате. Нашли ошибку сами — предложить правку текстом и ждать решения.
2. Показать Кириллу правку: файл, раздел, было → стало. Вносить только после его «да».
3. Проверить, что файл в Drive не менялся после снимка: `fileSize` и `modifiedTime` против `docs/product/README.md`. Изменился — сначала `/sync-product-docs`, правка — поверх свежего снимка.
4. Собрать новый текст в scratchpad: тело файла из снимка без строки-шапки, точечная замена (скрипт с проверкой, что заменяемый фрагмент найден ровно один раз), без пересказа остального.
5. Загрузить коннектором Drive `create_file` в ту же папку с тем же именем: `contentMimeType: text/markdown`, `disableConversionToGoogleType: true`, содержимое — ссылкой на файл (`sha256:…`), не текстом в вызове.
6. Прежний файл перенести в подпапку `_Архив версий` той же папки (`update_file` с `parentId`) и добавить к его имени дату (`01-statuses.md` → `01-statuses (до 2026-11-09).md`). Не удалять.
7. Сразу — `/sync-product-docs`: новый ID попадает в `docs/product/README.md`.
